# 数据字典与验证口径

## 正式 JSON 顶层字段

| 字段 | 含义 |
| --- | --- |
| `source_path` | 来源文件定位；本仓库合成样例仅使用 `synthetic://` URI。 |
| `spec_code` | 文档显示编号。 |
| `spec_code_key` | 规范化匹配键。 |
| `revision` | 修订版本；未知时可为空。 |
| `title` | 文档标题。 |
| `references` | 按原文顺序记录的引用数组。 |

## 引用记录字段

| 字段 | 含义 |
| --- | --- |
| `code` | 引用文档显示编号。 |
| `code_key` | 规范化匹配键。 |
| `title` | 引用标题或空值。 |
| `revision` | 引用修订版本或空值。 |
| `order` | 在当前文档中的顺序。 |
| `source_line` | 支持该引用判断的原文行；真实内容不进入本仓库。 |
| `source_path` | 引用证据来源；合成样例使用虚构 URI。 |
| `source_page` | 引用出现页码。 |

## “字段检查”不等于完整 Schema

原交付可证明百余份 JSON 的顶层字段集合一致，其数百条引用记录也使用一致的字段集合。现有材料没有独立、版本化的 JSON Schema 文件及完整类型、枚举和语义验证记录，因此对外应说“解析与允许字段检查通过”，而不是“完整 schema 合规率 100%”。

本仓库的合成演示脚本会额外检查类型、引用顺序、hash、manifest 和 coverage；该脚本是归档阶段为可复现展示而创建，不应倒推为原项目当时的完整代码流水线。
