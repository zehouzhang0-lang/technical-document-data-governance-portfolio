# 教师审阅简报

## 项目是什么

这是一个 AI 辅助的技术文档引用关系数据治理项目。任务不是开发应用界面，而是核对 PDF 原文、已有 JSON 与人工 Excel 清单之间的一致性，递归整理 root 文档及其子引用，并形成可复查的结构化交付。

## 我做了什么

- 将模糊需求拆成 root 识别、三源核验、递归展开、终端叶子、异常分流、质量验收和交付打包。
- 先用单树 demo 验证流程，再把剩余范围分配给多个隔离的 AI 会话并行处理。
- 定义写入边界、worker 报告和总控复核，避免并行结果互相覆盖。
- 对低清内容、缺失映射、同名文件冲突和信息性引用等边界进行人工判断并记录决策。
- 设计交付质量门禁，包括解析、允许字段、文件名、原始字节 hash、manifest 和 coverage。

## 已核验结果

- 处理数十棵 root 引用树，每棵均保留正式 JSON、review 文档、递归树和 evidence 结构。
- 数百条树内正式 JSON 记录全部映射到百余份最终交付文件。
- 解析、文件名唯一性、原始字节 SHA-256 与 coverage 机器检查全部通过。
- 识别多组同名、字节不同的候选版本，全部保留并通过重命名防覆盖。
- 归档复审将 JSON 解析、递归排序后仍发现多组语义重复，暴露出原去重口径仍可改进。
- 信息性引用的边界争议由人工复核者做出决定并保留变更记录。

这些结果证明交付结构与机器质检状态，不等于语义准确率 100%。项目没有官方逐条 gold standard，因此不主张 99% 准确率。精确项目统计因原材料权利与保密边界不在公开仓库披露。

## 为什么适合数据分析 / AIPM

对数据质量方向，它体现了多源对齐、清洗、标准化、异常识别、hash 归并、质量指标与可追溯交付。对 AIPM 方向，它体现了 AI workflow、Human-in-the-loop、SOP、风险分流和验收标准设计，也体现了事后审计发现口径缺陷并诚实纠偏。

它不应被包装为 BI/统计建模项目、完整 AI 产品、训练模型或已上线平台。

## 如何审阅本仓库

1. 先读 [`EVIDENCE_AND_CLAIMS.md`](EVIDENCE_AND_CLAIMS.md) 了解主张边界。
2. 再读 [`WORKFLOW_AND_DECISIONS.md`](WORKFLOW_AND_DECISIONS.md) 看流程与异常决策。
3. 查看 [`examples/synthetic/`](../examples/synthetic/) 中的合成演示。
4. 运行 `python scripts/security_scan.py` 与 `python scripts/verify_demo.py`。

真实工程图、技术规格、OCR 文本、原始 JSON 和 manifest 因版权、保密及出口管制风险不进入 GitHub；这项排除本身也是数据治理责任的一部分。
