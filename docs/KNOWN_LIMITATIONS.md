# 已知局限

- 没有官方逐条 gold standard，无法计算严谨的语义准确率、召回率或 F1。
- 低清扫描和 OCR 噪声仍可能产生残余语义风险；关键争议通过人工决策关闭，不等于风险消失。
- 项目属于数据质量治理与 AI 辅助工作流，不是传统 BI、统计建模或业务洞察项目。
- 没有上线产品、用户规模、转化率、A/B 测试或业务收益证据。
- 没有训练 OCR、NLP 或 LLM 模型。
- 多个 AI 会话的范围拆分不等于开发了多智能体编排系统，也不等于管理真人团队。
- 原始项目没有 Git 历史；过程主要由输出目录、prompt、review 文档和文件时间线证明。
- 原始可复用代码证据有限；本仓库的 QA 脚本是作品集归档阶段的安全重构。
- 原交付按原始文件字节 SHA-256 归并。归档复审仍发现多组规范化语义重复，因此“无重复内容”只能用于字节级口径。
- 历史质量报告没有完整的统一关闭映射；最终格式与 coverage QA 可证明，但不能声称所有树级历史问题均已闭环。
- 原 manifest、coverage 与 JSON 中含大量绝对路径，跨机器不可直接复现；本仓库合成样例改用相对路径和 `synthetic://` URI。
- 真实数据因版权、保密、复制限制和出口管制风险保持离线，仓库中的样例无法让第三方重新验证全部语义结论。
- 交付周期只有本地文件时间线的部分支持，没有外部工时记录，因此不作为公开简历的量化卖点。
